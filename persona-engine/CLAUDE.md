# Persona Engine — CLAUDE.md

Deterministic synthetic-personality runtime per PE-SPEC-001. Single-threaded
C99, no heap allocation in `process_input`, all math saturating fixed-point.
Target: < 10 ms / turn, < 300 KB / character on P3-class hardware.

The engine produces the *illusion* of inner life through inspectable state
transitions, not language generation. Every response is the deterministic
output of (state, input, today_seed, turn_count).

## Layout

```
persona-engine/
  include/persona.h         public API + all on-disk structs
  src/
    engine.c                process_input loop, drives, mood, emotion
    memory.c                episodic/semantic/short-term, salience, recall
    topic_goal.c            topic momentum, goal arbitration, intent
    dialogue.c              patterns, templates, slots, transforms,
                            repetition suppression, fallback ladder
    relations.c             per-user relation files, disposition decay
    today.c                 day-hash → today entry selection
    serialize.c             little-endian binary I/O, atomic rename
    rng.c                   xorshift32, seeded by today_seed + turn_count
  tools/compile_pretorius.c offline compiler: embedded source → char/*.bin
  test/repl.c               REPL harness with `:dump` / `:save` / `:quit`
  characters/pretorius/     binary character data (generated by compiler)
```

## File contract

Per the spec §3, each character is a directory of fixed-width little-endian
binary files. `identity.bin`, `drives.bin`, `dialogue/*`, `today.bin` are
read-only after load. `state.bin`, `memory.bin`, `relations/*.bin` are
rewritten atomically (`*.tmp` → `rename`).

Endianness is little-endian only (x86 native, no portability shim).

## Runtime invariants

- No `malloc`/`free` inside `process_input`. All buffers live in `Engine`.
- All decay is `delta_ms * rate`; clock is monotonic milliseconds.
- All RNG is xorshift32 seeded by `today_seed XOR turn_count` for replay.
- State is fully observable: `persona_debug_dump()` reproduces every variable
  that drove the last response.
- Drives are clamped 0..1000, mood -1000..1000 (saturating).
- Goals have 2-turn hysteresis unless an interrupt (insult → vindication).

## Build & run

```
cd persona-engine
make                              # builds libpersona.a, compile_pretorius, repl
make character                    # generates characters/pretorius/*.bin
./build/repl characters/pretorius # talk to Pretorius
```

REPL commands:
- `:dump` — full state dump (drives, mood, topic momentum, active memories)
- `:save` — force flush state + memory + relation
- `:user <id>` — switch interlocutor
- `:quit`

## Phase status

Implemented: Phases 1–5 minimal pass. State machine, agency, language
renderer, illusion layer (delay/bleed/callbacks), and the Pretorius corpus
(seed memories, obsessions, taboos, ~80 templates across intents, fallback
variants, 6 today-states).

Known intentional limitations (acceptable per spec §9):
- Pattern matcher is a sorted keyword table with binary search, not a full
  trie. Sufficient for ~100 patterns; swap-in-place if scale grows.
- Style transforms are direct function chain, not bytecode. Same determinism
  guarantee (seeded by template_id ^ today_seed).
- Crash-safety writes state every turn (cheap; <1 KB).

## Adding a character

Edit `tools/compile_pretorius.c` — the embedded text source — then run
`make character`. There is no separate authoring DSL; the compiler is the
authoring tool. Long-term: split into a text loader.

## Determinism / debugging

Same `today_seed` + same input sequence → byte-identical state and output.
The repl `:dump` is the canonical debugging surface. If a response feels
wrong, reproduce with the dumped seed and step through.
