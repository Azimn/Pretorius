# PersonaConsole V5 — Developer Workflow

A short, practical guide for working on the V5 C runtime across a Linux +
Windows team. Read it once; refer back when in doubt. The goal is that two
people on two operating systems can hand work back and forth without trees
drifting apart or breaking the engine's guarantees.

---

## 0. The non-negotiables (read first)

These are the project's invariants. A change that violates one is wrong even
if it compiles and "seems better":

1. **The cartridge is the character; the model is a renderer.** Behavior lives
   in the engine + cartridge, not in generated text.
2. **Memory firewall.** No renderer/LLM output ever becomes memory. Layer-1
   writes carry a `MemorySource`; `PE_SRC_RENDERER_OUTPUT` is always denied.
3. **Behavioral holography (determinism).** Same seed + WAL + inputs ⇒
   identical identity state, on every platform and every renderer. Only
   wording may vary.
4. **Continuity beats sophistication.** A duller-but-stable character beats a
   cleverer-but-unstable one.

If a task seems to require breaking one of these, stop and discuss it first.

---

## 1. Environment

Same toolchain on both platforms — `gcc` + POSIX:

- **Linux:** `gcc`/`cc`, `make`, `node` (for the JS test harnesses).
- **Windows:** **Cygwin** with `gcc`, `make`, and `node`. Run all `make`
  commands from a Cygwin shell. The PowerShell release scripts prepend
  `C:\cygwin64\bin` to `PATH` for you.

Native MSVC is **not** supported (it has no POSIX layer). Don't add Visual
Studio project files or `_WIN32` code paths — see §6.

---

## 2. Git workflow (this is what prevents "version mismatch")

**Use the shared remote, not zip handoffs.** The single biggest source of pain
has been exchanging zipped trees. Don't. Always go through git:

```bash
# start of every task
git fetch origin
git checkout <feature-branch>
git pull --rebase origin <feature-branch>

# ... do work, build, test (see §3) ...

git add <specific files>          # not `git add -A` blindly
git commit -m "clear message"
git push origin <feature-branch>
```

- **One branch per task.** Keep `main` clean; open a PR to merge.
- **Pull before you start and before you push.** Rebasing on the latest avoids
  the divergence that turns into a painful manual merge.
- **Small, focused commits** with messages that say *why*, not just *what*.
- **Never force-push a shared branch** without agreeing first.

### One-time setup after pulling the `.gitattributes`

The repo now normalizes line endings (LF everywhere; CRLF only for
`*.ps1/*.cmd/*.bat`; cartridge binaries protected). Do this **once** so your
working tree matches the new policy:

```bash
git add --renormalize .
git commit -m "Normalize line endings to repo policy"   # only if it lists changes
```

After that, line endings are automatic and you should never again see a diff
that's "every file changed." If you do, it means a `.gitattributes` rule is
missing for that file type — fix the rule, don't commit the churn.

## 3. Build & test — the green gate

**Every push must leave the full suite green.** Run it before you push:

```bash
make host              # build the runtime binary
make                   # libs, tools, profiles, cartridges
make v4_all_tests      # the full gate — must end with "--- V4 tests: green ---"
```

Useful subsets while iterating:

```bash
make v4_modules_run            # engine subsystem unit tests
make v4_replay_run             # determinism + cross-renderer holography
make v5_believability_run      # "does it feel alive" trial
make v5_transcript_quality_run # short-reply / anti-repeat quality
```

If a test fails, fix the root cause — don't weaken the assertion to make it
pass. If an assertion is genuinely wrong, change it in its own commit with an
explanation.

The Windows-only release gates (`make release_check`, `make demo_package`) run
PowerShell and must be run on Windows; they are not part of `v4_all_tests`.

## 4. Cartridges & binary artifacts

Character data is compiled from C, not hand-edited:

- Edit the source: `tools/compile_pretorius.c` (or `compile_kiki.c`), then
  `make` regenerates `profiles/<char>/dialogue/*.bin`, `identity.bin`, etc.
- **Commit the source change and the regenerated `*.bin` together** in the same
  commit, so source and artifact never disagree.
- **Never hand-edit a `.bin`/`.lm`/`.cart`** and never apply text tools to them.
  They are packed-struct binary ABI; the `.gitattributes` marks them `binary`
  so git won't touch line endings — keep it that way.
- `*.cart` is a build output and is **gitignored** (regenerated by `make`); the
  individual section `*.bin` files *are* tracked.
- Runtime state files (`state.bin`, `memory.bin`, `chapters.bin`,
  `reflections.bin`, `aether/*`) are written by the running host. Don't commit
  changes to them that came from a test/REPL run — `git checkout --` them.
- Cartridge struct capacities are part of the ABI. If you change a capacity in
  a header, **all cartridges must be regenerated** (`make`).

## 5. Determinism rules (protect holography)

The replay/holography tests will catch most violations, but know the rules so
you don't write them in the first place:

- **Randomness:** only via the seeded engine PRNG (`persona_rng_u32(&eng->state)`).
  Never `rand()`, `random()`, addresses, or uninitialized memory.
- **No wall-clock in canonical paths.** Time enters through the engine's clock
  / WAL, not ad-hoc `time(NULL)` inside decision logic.
- **No floats in the engine hot path.** Affect/decay/scoring use saturating
  fixed-point integer math (see `memory/affect_curve.c`). Floats round
  differently across compilers/platforms and break holography.
- **Sorts must be total orders.** Any `qsort` comparator must break ties on a
  stable secondary key (qsort isn't stable; equal-comparing elements would
  reorder per-platform). Returning `0` on a tie is a bug.
- **Fixed-width integer types** (`uint16_t`, `int32_t`, …) for any value that
  is serialized or compared; mind signed/unsigned in arithmetic and casts.

---

## 6. Cross-platform code rules

- **POSIX/C99 only.** The sources contain zero `_WIN32`/`__linux__` `#ifdef`s —
  keep it that way. Use only the interfaces listed in `PORTABILITY.md`
  (Cygwin provides them on Windows).
- **No Linux-only APIs** (`epoll`, `eventfd`, `<linux/*>`, `SO_REUSEPORT`,
  `accept4`, …). Use portable `select`/`poll`, plain BSD sockets, etc.
- **Forward-slash paths**, relative to the cartridge dir. Never hardcode `\`,
  drive letters, or absolute paths.
- **LF line endings** in all source (enforced by `.gitattributes`/`.editorconfig`).
- Keep the engine binary **character-agnostic**: no hardcoded character names
  or keyword checks in `core/`. Character data lives in cartridges.

---

## 7. Quick checklist before every push

- [ ] Pulled/rebased on the latest of my branch.
- [ ] `make v4_all_tests` ends in `--- V4 tests: green ---`.
- [ ] Touched a cartridge source? Regenerated `*.bin` and committed them together.
- [ ] No stray runtime-state files or build outputs staged.
- [ ] No new floats / `rand()` / wall-clock in canonical engine paths.
- [ ] No `_WIN32`/Linux-only APIs added.
- [ ] Commit message explains *why*.

When in doubt, prefer the change that keeps the character **stable and
identical across machines** over the one that's cleverer.
